## 项目

打开 Vite 打印的本地地址。选择**打开项目**，从本地列表中挑选一个项目；或使用**选择项目文件夹…**直接选中项目文件夹。项目包含 `rig.json`、`source.png` 和 `built/`。**仅加载 rig.json…**只替换绑定配置，不加载图片。顶栏显示项目名称，并提供复制完整路径和打开文件夹的按钮。**保存绑定**和 Ctrl/Cmd+S 会把列表中的项目直接保存到 `rig.json`，旧文件保留为 `rig.json.bak`。示例是只读的；通过浏览器选择的文件夹则以下载 JSON 的方式保存。只有通过 127.0.0.1 上的开发服务器才能访问本地项目；静态构建版本保留文件夹选择器和下载保存的流程。图片始终留在本机。**最近打开**在此浏览器中最多保留十个打开过的项目，并可在启动时重新打开上次的项目。可以在项目菜单中移除单条记录、清空历史，或关闭自动重新打开。支持的浏览器会为选中的文件夹保留目录句柄，可能会再次请求授权；其他浏览器则显示**重新选择文件夹**。历史记录中绝不存储图片数据。

文件布局、清单、图层与差分图片元数据、兼容性规则以及整个文件夹的校验，见[虚拟形象文件与文件夹格式](format.zh.md)。

## 手动构建项目

图层构建器需要 Python 3.10+ 和 [uv](https://docs.astral.sh/uv/)。它借助 NumPy、Pillow 和 OpenCV 在本地运行；这些是构建工具，不是浏览器依赖。其他 Python 工具以内联方式声明依赖，可直接用 `uv run` 运行。校验器和姿态渲染器使用 Node.js 22.17+；如有需要，用 `npm ci` 安装 Node 依赖，用 `npx playwright install chromium` 安装 Chromium。[绑定字段说明](rig-fields.zh.md)解释了坐标和摆放方式。

1. 创建项目文件夹，把插画放入 `source.png`。透明背景的 PNG 即可。试验时请使用画作的副本。
2. 准备 `rig.draft.json`。以 `samples/miko-qipao/rig.json` 作为结构示例，把 `image.width` 和 `image.height` 设为图片尺寸，并以原图像素为单位放置几何形状。沿睫毛内侧描出每只眼睛的 `opening`，并让外围的 `roi` 包住睫毛和眼睑线条。发束的 `nodes` 从发根到发梢依次放置。没有 `hand`、`buns` 和 `accessories` 时将其删除；保留必需的头部、身体、五官、嘴巴、腮红、网格和取景范围设置。草稿中可以省略眼睛的 `x0`、`x1`、`top` 和 `bot` 字段。
3. 在仓库根目录构建图层：

   ```sh
   uv run --with numpy --with pillow --with opencv-python-headless tools/build-layers.py /path/to/project --rig rig.draft.json
   ```

   这会写入 `rig.json`（每只眼睛的上、下曲线各采样 24 个点），以及 `built/base.png`、`built/hairmask.png`、每只眼睛的四个 `eye{i}_ball/lash/low/crease.png` 图层和 `built/layers.json`。手部和饰品图层只在绑定中存在对应设置时生成。输入草稿保持不变。已生成的文件会被替换；可选的绘制差分图片会保留。不加 `--rig` 时，输入为 `rig.json`。
4. 在编辑器中选择**打开项目**并从列表中选中它，或浏览选择整个项目文件夹（包含 `source.png`、`rig.json` 和 `built/`）。用**姿态测试**检查眨眼和面部角度，用**连续测试角度**检查完整的动作范围。

构建器会在每只眼睛的 ROI 附近估算眼睑皮肤和线条颜色，在发束线条和发髻附近估算头发颜色。它在头部、发髻和发束区域内沿连通的颜色区域追踪，并利用附近的皮肤和身体颜色排除非头发像素。明亮的头发高光或包含多种不相关颜色的头发，可能使推断出的蒙版出现缺口。它不会自动描出眼睛，也不会凭空补出被遮挡的画作。轮廓不准确时，眨眼可能残留眼睛像素，或把皮肤包进移动的图层。请检查结果并在编辑器中调整绑定。对于从本地列表打开的可写项目，可在轮廓修改提示横幅中选择**保存并重建图层**。它会运行本地构建器并重新加载预览，同时保留选中状态、缩放和撤销历史。构建失败时保留之前的图层，并提供日志。通过浏览器选择的文件夹仍需先保存 JSON，再运行不带 `--rig` 的命令，然后重新打开文件夹。想保留原始草稿的话，请另行存放。绘制的闭眼和嘴型差分是可选的。

饰品的颜色蒙版目前在每个 `box` 内使用绑定中的红色占比阈值（`color.redness` 和 `color.minRed`）。头发和皮肤估算假设所描区域周围的像素有足够的不透明度；完全半透明的画作，或眼睛 ROI 内的不相关颜色，可能需要手动修补。图像修补（inpainting）只是近似还原被手部和眼睛遮挡的画作。

## 编辑

- 拖动控制点，或选中某一项来编辑它的数值字段。
- 双击多边形／折线的边可插入顶点；按住 Alt 点击顶点可将其删除。
- 捏合可在光标处缩放；双指滚动用于平移。鼠标滚轮默认缩放；**鼠标滚轮**选项可切换为平移。Ctrl/Cmd+滚轮始终缩放。
- 拖动空白处、空格+拖动或中键拖动可平移。用 **− / +** 缩放，点击百分比回到 100%（一个图像像素对应一个屏幕像素），**适应画布**显示整张图片，**定位选中部件**聚焦当前部件。在列表中双击部件同样会定位到它。缩放范围为 10% 到 1600%，控制点始终保持相同的屏幕大小。
- Ctrl/Cmd+加号、减号、0 和 1 分别用于放大、缩小、适应画布和重置到 100%。输入框获得焦点时，这些快捷键不会干预浏览器的默认行为。
- **撤销**／**重做**可恢复编辑。键盘快捷键：Ctrl/Cmd+Z、Ctrl/Cmd+Shift+Z 和 Ctrl/Cmd+S。
- **保存绑定**会保存列表中的项目；通过浏览器选择的文件夹则下载 JSON。拖入 JSON 文件同样可以加载。
- 暂停**待机动作**可获得稳定的姿态便于对比，或用**连续测试角度**扫掠各个角度。
- 在预览下方的**姿态测试**和**嘴型测试**标签页之间切换。**嘴型测试**可保持 あ・い・う・え・お・ん 的口型，或以每秒 4–12 个音拍的速度播放假名文本。**松开嘴型**／**停止**把控制权交还给姿态滑块。有绘制的嘴型图片时优先使用；否则由网格嘴巴做动画。此检查不播放声音。

**表情差分**显示眼睛和嘴型图片的数量。勾选想要的差分，复制为 **Codex** 或 **Claude Code** 准备好的请求。Codex 的请求会使用其内置生图功能、在本地导入并进行姿态审查；卡片上会注明图片将发送给 Codex 生图服务。Claude Code 的请求则让它准备蒙版和提示词，说明差分图片应保存到哪里，然后停止。接收请求的助手会被记住。本地项目 `variants/` 和 `built/sprites/` 目录中的变化会就地重新加载，保留未保存的轮廓、选中状态、缩放和撤销历史。示例的请求会让编程助手在 `projects/` 下的副本上工作，原示例保持不变。

**自己准备差分图片**默认折叠。展开后可用 `variant-requests.py` 在本地导出蒙版和提示词，或按列出的文件名拖入／选择与原图尺寸相同的 PNG。编辑器在构建差分图片前会校验尺寸和蒙版外的像素；导入被拒绝时，之前的差分图片和图层保持不变。手动导出和导入需要通过开发服务器打开的可写项目。应用把图片留在本地；Codex 卡片会在你复制请求之前说明生图上传一事；该请求不包含其他外部服务。

## 光照

**光照**是可选功能，默认关闭。展开**姿态测试**和**嘴型测试**标签页下方（或直播页面底部附近）折叠的**光源与阴影**区域，勾选**启用光照**。区域展开时，预览上会出现光源控制点；可以拖动它，或让它获得焦点后用方向键移动（按住 Shift 移动幅度更大）。启用光照时，区域标题显示**开**。

用于明暗处理的形状由单张图片推断而来：每个图层的轮廓被圆润化，头部视为椭球，深色绘制线条带来浅浅的凹凸。首次启用光照时，每个图层计算一次。画作中绘制的阴影会保留；光源使背光一侧颜色加深，受光一侧保持原有绘制颜色。

| 控件 | 效果 |
|---|---|
| 光源高度 | 数值低时从侧面打光；数值高时从正面打光 |
| 光照范围 | 光源在衰减前能照多远 |
| 光照强度／环境光 | 直射光与均匀的基础光 |
| 光源颜色／环境光颜色 | 直射光和环境光的颜色 |
| 明暗强度 | 原始画作与光照结果的混合程度 |
| 明暗过渡 | 受光区与背光区之间过渡的宽度 |
| 光泽／轮廓光 | 细小的高光，以及朝向光源的边缘上的光 |
| 线条凹凸 | 从发丝等绘制线条中提取的凹凸 |
| 着色方式 | **柔和**或**赛璐璐**（阶梯式，动画风格） |
| 投影 | 虚拟形象背后与光源方向相反的柔和轮廓阴影 |

**重置光照**恢复默认值。这些设置只影响显示：不会保存到 `rig.json`，但每个项目会在此浏览器中记住它们。关闭光照时，虚拟形象的渲染效果与没有该功能时完全一致。

### 光照预设

直播页面的**光源与阴影**区域有八个预设栏位，例如普通光照、恐怖游戏用的从下方打来的红光，以及夕阳色调。**保存**会把当前所有光照设置（位置、颜色、着色方式以及开关状态）存入该栏位；再次保存会覆盖。点击已保存的栏位，或在直播页面处于焦点时按 **Shift**+**1**–**8**，即可立即切换。色块显示光源颜色和环境光颜色。与当前光照一样，预设按项目保存在此浏览器中。

预设不会改变表情，表情也不会改变光照，两者可以独立切换。想回到普通光照，把它保存到某个栏位（例如 1），再切换到该栏位即可。切换到空栏位不会有任何变化。

其他应用切换预设的方式与[表情](#从其他应用切换表情)相同，使用同一个令牌：向 `/__live/lighting`（显示在预设下方的**预设请求 URL**）发送 `POST`，JSON 正文如 `{"preset": 2}`。编号为 1–8，`"project"` 的用法与表情相同。

```sh
curl -X POST http://127.0.0.1:5173/__live/lighting \
  -H "X-Studio-Token: <token>" -H "Content-Type: application/json" \
  -d '{"preset": 2}'
```

## 直播与推流

由开发服务器（`npm run dev`）提供的两个页面：

- **直播页面**（`/live.html?project=<name>`，或编辑器顶栏的**直播**）：摄像头和麦克风控制、面部追踪、校准以及直播地址。
- **直播画面**（`/stream.html`）：只显示虚拟形象，供 OBS 或其他采集软件使用。

### 直播画面 URL

| 参数 | 取值 | 默认 |
|---|---|---|
| `project` | 本地列表中的项目名，或 `sample-miko-qipao` | 示例 |
| `avatar` | 与本地开发服务器同源的文件夹或 `.mavatar` URL；显式指定 `project` 时优先 | 未设置 |
| `bg` | `transparent`、`green`、`blue` 或十六进制颜色（如 `#336699`） | `transparent` |
| `fit` | `contain`（完整形象）或 `cover`（填满画面） | `contain` |
| `idle` | `1`（待机动作：眨眼、呼吸、头发摆动）或 `0` | `1` |
| `light` | `1` 启用[光照](#光照)；省略则不启用光照 | 关闭 |
| `lx`, `ly` | 光源在画面中的横向和纵向位置，`0`–`1` | `0.2`, `0.2` |
| `lz` | 光源高度，`0.1`–`2` | `0.45` |
| `lr` | 光照范围，`0.2`–`3` | `1.2` |
| `li`, `la` | 光照强度 `0`–`2`，环境光 `0`–`1` | `0.8`, `0.4` |
| `lc`, `lac` | 光源和环境光颜色，六位十六进制数，不带 `#` | `ffffff`, `eef0f8` |
| `ls`, `lf` | 明暗强度和明暗过渡，`0`–`1` | `0.8`, `0.45` |
| `lsp`, `lrim`, `ld` | 光泽、轮廓光和线条凹凸，`0`–`1` | `0.12`, `0.3`, `0.4` |
| `lm` | `soft` 或 `cel` | `soft` |
| `shadow` | `1` 添加投影 | `0` |

其他任何 `bg` 值都会回退为透明。超出范围的光照数值会被截断到边界，无效值使用默认值。**复制OBS地址**和**在新标签页打开OBS画面**会带上直播页面当前的光照设置。在 OBS 中把该地址添加为**浏览器来源**（例如 1080 × 1080）；透明背景无需色度键。不支持透明的软件请选用绿色或蓝色。

`avatar` 接受相对 URL，或与 Studio 同源（协议、主机和端口相同）的 HTTP(S) URL。外部或无效的 URL 会被忽略并改为加载示例；不会触发外部请求。存在 `project` 时，`avatar` 被忽略。

### 动作如何传到直播画面

- 直播页面通过开发服务器的 WebSocket 发送数值姿态（头部角度、眼睛、视线、眉毛、嘴巴），每秒最多 60 次。服务器只接受格式正确的数值消息并转发；每个直播画面只应用属于自己 `project` 的消息。
- 更新停止一秒后，直播画面会平滑回到待机动作。
- 直播页面的光照变化以同样方式到达匹配的直播画面。服务器只接受由数字和列出的选项组成的完整设置。
- 追踪在 Web Worker 中运行，因此直播页面被隐藏时仍会继续：无论是切到其他标签页、最小化，还是被其他窗口挡住。可用时帧来自 `MediaStreamTrackProcessor`，否则来自 `requestVideoFrameCallback` 或 worker 定时器。如果追踪仍然停止或变慢，直播页面会显示警告；请把它的窗口切到前台。
- Face Landmarker 使用 GPU；若 GPU 失败或预热后仍然缓慢，会一次性切换到 CPU。
- 开启麦克风时，音量驱动嘴巴张开程度，摄像头则保持嘴型。项目中有绘制的嘴型图片时会自动使用。

### 表情

直播页面上折叠的**表情**区域可把面部切换为普通、微笑、害羞、惊讶、半眯眼、生气、难过或眨眼。直播页面处于焦点时，按 **1**–**8** 键效果相同，即使区域已关闭；按 **1** 或"普通"按钮回到普通表情。按下当前已显示表情对应的按键会保持该表情。在表单字段中输入的按键会被忽略。区域标题显示当前表情。浏览器只把按键交给处于焦点的页面；想在其他应用位于前台时切换，请使用[其他应用](#从其他应用切换表情)。

表情叠加在追踪之上：眨眼、视线和嘴巴继续跟随摄像头或麦克风，而眼睛、眉毛和腮红保持表情状态。切换时平滑过渡。表情也会在不使用摄像头或麦克风的情况下传到直播画面。眉毛被刘海遮住时，半眯眼、生气和难过之间的差异会变小。

### 从其他应用切换表情

快捷键应用和 Stream Deck 等按键面板可以在 OBS 等其他应用位于前台时切换表情。它们向开发服务器发送请求，由服务器转发给直播页面；请保持直播页面打开。

在直播页面打开**表情 → 从其他应用切换**，复制请求 URL 和令牌。每个请求为：

- 向请求 URL 发送 `POST`，例如 `http://127.0.0.1:5173/__live/expression`
- 请求头 `X-Studio-Token: <token>`（或 `Authorization: Bearer <token>`）
- JSON 正文如 `{"expression": "smile"}`。名称：`neutral`、`smile`、`shy`、`surprise`、`halfLidded`、`angry`、`sad`、`wink`。加上 `"project": "<name>"` 可只发送到该项目的直播页面。

发送当前已显示的表情会保持它；发送 `neutral` 回到普通面部。

**macOS 快捷指令**

1. 在"快捷指令"应用中打开**设置 → 高级**，启用**允许运行脚本**。
2. 创建一个快捷指令，添加**运行 Shell 脚本**操作，把其中的文本替换为下面的命令（见**命令行**），并使用你的令牌。给快捷指令命名，例如"Avatar Smile"。
3. 用 ▶ 按钮运行一次，确认直播页面发生变化。
4. 在快捷指令的详细信息中选择**添加键盘快捷键**，按下要使用的按键。
5. 为每个表情复制一份快捷指令，并修改命令中的 `smile`。

macOS 通过"服务"菜单运行这些键盘快捷键，因此并非在所有应用中都生效：测试中 OBS 在前台时有效，访达在前台时无效。在快捷指令的详细信息中启用**用作快速操作 → 服务菜单**可能有帮助。想让按键在任何应用中都生效，可用 Raycast、Hammerspoon 等热键工具运行同一条命令，或使用 Stream Deck。

**Stream Deck**：使用能在后台发送网络请求的插件操作，设为 POST，使用相同的 URL、请求头和 JSON 正文，每个表情分配一个按键。内置的**网站**操作会打开浏览器标签页，因此不适用于此用途。

**命令行**（也可从 AutoHotkey 或其他工具调用）：

```sh
curl -X POST http://127.0.0.1:5173/__live/expression \
  -H "X-Studio-Token: <token>" -H "Content-Type: application/json" \
  -d '{"expression": "smile"}'
```

令牌保存在 `projects/.expression-token` 中，该文件不纳入版本控制。**重新生成令牌**会替换它；使用旧令牌的快捷方式随后会收到 `401`。只有本机上的应用能访问该服务器。浏览器中打开的网站既无法读取令牌，也无法发送令牌请求头。

### 不使用摄像头

摄像头是可选的。只开麦克风时，虚拟形象保持待机动作（眨眼、视线、呼吸、头发摆动），由你的声音驱动嘴巴开合。没有摄像头时，嘴巴保持一种形状，只改变张开程度；项目中有绘制的嘴型图片时仍会使用。

### 全身追踪（实验性）

**追踪身体动作（实验性）**默认关闭。关闭时，直播与以前一样只追踪面部，不会加载 Pose Landmarker 模型。其行为和设置可能会变化。

开启后，追踪 worker 还会每隔一帧面部画面运行一次本地的 Pose Landmarker lite 模型，只返回肩膀、髋部、手肘和手腕的数值位置。直播页面会列出当前加载的虚拟形象跟随的部位：

- **上半身**（所有虚拟形象）：肩膀动作驱动身体摇摆和倾斜。
- **腿部**（设置了 `legs` 的虚拟形象）：可见的髋部驱动重心转移。髋部不在画面中时（例如坐着），重心转移保持待机动作。
- **手臂**（设置了 `arms` 的虚拟形象）：手肘和手腕驱动小幅摆臂和屈肘。手臂不会抬起；参见[绑定字段说明](rig-fields.zh.md)中可选下垂手臂一节。

请在放松站立、双臂下垂时校准。微小的肩膀动作会被忽略；手臂离开校准姿态时，身体保持之前的倾斜，因此手臂动作不会被误认为身体倾斜。离开画面的关节会保持姿态 500 毫秒，然后回到待机状态。

摄像头检测的身体位置不如面部追踪稳定，裙子等衣物可能比预期摆动更多。想让它们安静下来，可提高**动作平滑度**，或在 Studio 的**身体 → 布料**中把每件衣物的 `responseGain` 调低、趋近 `1`（物理值）。该值保存在绑定中，因此直播画面也会使用它。原生运行时会忽略 `arms`。

### 口型动作设置

Studio 的**嘴型测试**标签页提供五种风格：舒缓、标准、轻快、含蓄和鲜明。选择后立即用假名预览口型动作。打开**精细调整**可调整口型动作、张嘴幅度和闭嘴方式；拖动滑块会选中**自定义**，松开后即预览效果。用户启动的假名语句在设置变化时保持当前播放位置。展开区域中还包含由响度驱动的本地音频文件预览。预览文件留在浏览器中，不会包含在虚拟形象导出里。

每项动作设置接受 0 到 1 之间的有限数值，默认为 0.5：

| 设置 | 0 | 0.5（原有行为） | 1 |
| --- | --- | --- | --- |
| `granularity` | 只有大的响度低谷才分隔音节；合并短的假名音拍。 | 原有灵敏度。 | 更小的低谷即可分隔音节；假名闭合更明显。 |
| `openness` | 张开幅度乘以 0.55。 | 原始张开幅度。 | 张开幅度乘以 1.25，上限为 1。 |
| `closeSpeed` | 缓慢释放（6/s）。 | 原有的音频 32/s、假名 22/s 释放速度。 | 快速释放（45/s）。 |

可在创建运行时实例时配置，或在播放过程中更新设置：

```ts
import { createMeshAvatar, type LipSyncSettings } from 'mesh-avatar';

const settings: LipSyncSettings = { granularity: 0, openness: 0.5, closeSpeed: 0 };
const avatar = await createMeshAvatar(canvas, { rig, assets, lipSync: settings });
avatar.setLipSync({ openness: 0.75 }); // retains the current movement and closing settings
avatar.setSpeaking(true);
avatar.setVoiceLevel(level); // normalized audio loudness, 0–1
```

`setLipSync(settings: LipSyncSettings): void` 是部分更新：省略或为 undefined 的字段保持当前值。空设置和省略创建选项都使用原有行为；显式把三个数值都设为 0.5 会产生完全相同的动作和随机抽样。无效对象、非有限数值以及超出 0–1 的值会在修改设置之前抛出异常。张嘴幅度也会影响保持口型的预览。较低的假名粒度会把相邻的短音拍合并，并弱化短暂的闭合；长停顿仍会闭嘴。

可写项目会把这些数值和可选的编辑器选择保存在 `avatar.json.lipSync` 中；通过浏览器选择的文件夹和只读示例的导出也会包含它们。`loadMeshAvatar` 会应用这些保存的值，显式的 `options.lipSync` 字段优先。直播页面和浏览器 Player 会把虚拟形象的设置应用到现有的麦克风响度路径上。仅加载虚拟形象不会启动麦克风。

自定义元素暴露 `element.lipSync: LipSyncSettings`（可读写）和 `element.setLipSync(settings: LipSyncSettings): void`。赋值和方法调用都是部分更新。getter 返回显式覆盖值的副本；这些覆盖在更换素材源或画面适配后仍然保留，其余情况应用虚拟形象保存的值。可选的 `preset` 字段（`calm`、`default`、`lively`、`subtle`、`big`、`custom`）只记录编辑器的选择；播放始终使用三个数值。React 封装通过 ref 暴露该元素，因此请调用 `ref.current.setLipSync(...)`；它没有专门的设置 prop。

### 表情的张嘴幅度

直播表情可以设置静止时的张嘴幅度，适用于内置值不合适的绘制形象。把它保存在 `avatar.json.expressions` 中（见[格式说明](format.zh.md)），或在创建虚拟形象时传入相同结构：

```ts
import { createMeshAvatar, type ExpressionSettings } from 'mesh-avatar';

const expressions: ExpressionSettings = { surprise: { mouthOpen: 0.45 } };
const avatar = await createMeshAvatar(canvas, { rig, assets, expressions });
avatar.setExpression('surprise'); // rests at 0.45 instead of 0.6
```

`mouthOpen` 对 `smile`、`shy`、`surprise`、`halfLidded`、`angry`、`sad` 和 `wink` 接受 0 到 1 之间的有限数值。省略的表情和省略的选项保持内置值（surprise 为 0.6，其余为 0），因此输出不变。`loadMeshAvatar` 会应用保存的值，每个表情都以显式的 `options.expressions` 字段优先。无效对象和超出 0–1 的值会抛出异常；未知的表情名称和字段会被忽略。`neutral` 不改动这些参数，因此为它设置的条目没有效果，同样会被忽略。

### 视频通话

想在 Zoom、Google Meet 等视频通话应用中使用虚拟形象，请在 OBS 中显示直播画面并启动 OBS 的**虚拟摄像头**：

1. 把直播地址作为**浏览器来源**添加到 OBS 场景。透明背景在虚拟摄像头中会变成黑色，因此请选择一种颜色，或在虚拟形象背后添加图片来源。
2. 在 OBS 中选择**启动虚拟摄像头**。macOS 上首次使用需批准摄像头扩展。
3. 在视频通话应用中选择 **OBS Virtual Camera** 作为摄像头。音频请直接选择你的麦克风。

通话期间保持直播页面运行。许多视频通话应用只镜像你自己的预览；其他参与者看到的虚拟形象与 OBS 中显示的一致。

### 隐私

摄像头画面和麦克风音频在浏览器中处理，绝不离开你的电脑。只有上述数值姿态会通过本地 WebSocket 传输。MediaPipe 运行时和模型由本地提供；不会请求 CDN 或远程模型，两个页面中任何一个向 `127.0.0.1` 之外发起请求，端到端测试都会失败。

`@mediapipe/tasks-vision` 锁定在 0.10.21，因为更新的版本包含向 Google 发送使用日志的代码。升级前请阅读 [vendor/mediapipe/README.md](../vendor/mediapipe/README.md)。

### 故障排查

- **没有摄像头画面**：浏览器询问时允许摄像头访问。macOS 上还要在"系统设置 → 隐私与安全性 → 摄像头"中检查你的浏览器。推荐使用 Chrome。
- **动作太小或抖动**：提高**灵敏度**，或提高**动作平滑度**。面向摄像头、面部放松，重新校准。
- **左右颠倒**：切换**镜像**。
- **虚拟形象闪烁或表情来回切换**：项目可能在两个直播标签页中打开；出现这种情况时直播页面会显示警告。直播画面只跟随其中一个，但其他应用发来的切换会到达两个页面。请关闭不用的标签页。
- **直播画面一直停留在待机状态**：保持直播页面打开并运行，并确保两个页面使用相同的 `project`。
